## AI-REC-01 — selected procedures and checklist references disagree

**Observed symptom.** The first historical run `c69427be-7f75-402f-9c14-5e73d6a1027f` failed at 2026-10-05T02:10:57.135Z with `INVALID_REFERENCE`, latency 38,320 ms. The audit records attempt 1 and attempt 2 as `ACTION_SOURCE_NOT_IN_PROCEDURE`; both are retained. All six prerequisite tool calls succeeded, including retrieval of five real sources. The request remained TRIAGED v3, unassigned, with no SLA. A later user retry `95e70de8-2ab2-44dd-b1f2-d095d5e6ca8d` succeeded in 18,037 ms; it is a separate run and does not erase the original failure.

**Expected contract and owners.** [AI_BEHAVIOR_SPEC](../specs/AI_BEHAVIOR_SPEC.md) and [RAG_SPEC](../specs/RAG_SPEC.md) require every checklist source to belong both to the captured retrieval and to the returned procedureSources. `apps/api/src/ai/recommendation-output.ts`, `parseRecommendationV2` → `validateBindings`, first checks retrieved-source membership, then checks checklist/action membership in procedureSources. The same parser additionally requires actual KNOWLEDGE evidence and verbatim excerpts. The validator correctly rejected the historical artifact; this is not a timeout or an overly strict validator.

**Confirmed causal mechanism.** At release prompt/native format `grounded-recommendation.v2.10`, `apps/api/src/ai/prompts/recommendation.ts::recommendationFormatV2` allowed procedureSources to select one or two IDs from all retrieved sources, while each suggestedChecklist.sourceIds independently selected from that same global enum. With retrieved sources A and B, procedureSources=[A] plus checklist.sourceIds=[B] satisfies those independent generation constraints but violates the publication contract. The backend maps V2 suggestedChecklist into the existing action validator, so this exact relation produces `ACTION_SOURCE_NOT_IN_PROCEDURE`. The retained earlier controlled reproduction `artifacts/v130-stability-20261005/baseline-causes.json` confirms the mismatch. No source-to-source substitution is necessary to explain it.

**Evidence limit.** Historical polling deliberately returns `recommendation:null` and `evidence:null` for this failed run. The preserved audit contains safe validation categories, not the raw model payload. No integrity-checked captured raw output was found in the supplied artifacts. **REC-01 exact captured-payload replay: NOT AVAILABLE.** The deterministic A/B reproduction is an equivalent validation-boundary regression, not a replay of either captured historical attempt and not new inference. It proves the independently identified generation/validation gap; the exact offending historical source pair remains unknown.

**Fix and regression design.** Candidate generation revision `grounded-recommendation.v2.11` enumerates sufficient branches for each allowed one/two-source selection, binds the procedure tuple to its required KNOWLEDGE evidence, and restricts the checklist source enum to that selected subset. Conflict branches retain their required evidence within the existing three-evidence-item generation budget. Insufficient-evidence handling, public `recommendation.v2`, parser, source availability, model, token/deadline/attempt bounds and human decision semantics remain unchanged. No post-generation step adds a source or silently repairs invalid output.

`scripts/evaluation/m15-prompt.test.mjs` builds a cross-procedure A/B artifact, asserts the unchanged parser rejects it with the exact rule, and asserts each native branch's checklist IDs equal its procedure IDs and include the required evidence. This is a behavioral/schema relation test, not a snapshot of prompt prose. Unknown/foreign IDs, fabricated excerpts, insufficient evidence, privacy/scope and exhausted bounded attempts remain separate parser/integration cases. `recommendation-unit.log` records nine tests passed. Full accepted M15 and targeted live results must be assessed independently in verification.

## AI-SUM-01 — valid event IDs permit unsupported actor and cause claims

**Observed symptom.** Historical summary run `f73aba6c-bc3c-4948-95fa-9a84ccfe9964` succeeded syntactically in 9,890 ms. Its COMPLETE_AI_ANALYSIS event at 02:08:16.035Z says “AI hoàn thành phân tích, xác định nguyên nhân giả lập.” The later resolution at 02:23:30.997Z contains STAFF's synthetic APN cause, repair and verification. Another historical timeline phrase presents START_AI_ANALYSIS as an attempt to identify the cause. Actual intake only classified the request and suggested priority. Correct event IDs and chronology therefore did not establish the truth or attribution of those sentences.

**Expected contract and owners.** `OperationalAiService.executeSummary`, `ai/operational-output.ts` and [AI_BEHAVIOR_SPEC](../specs/AI_BEHAVIOR_SPEC.md) own resolution summaries. Submitted rootCause/resolution/verification must remain STAFF facts, with synthetic labels and negation preserved. Event text cannot invent a result, attribute later facts to AI, or infer a cause from event order. Public/private projection ownership remains under authorization and collaboration contracts.

**Confirmed causal mechanism.** The release syntactic parser constrains executive/timeline shape; the summary execution path checked event membership and order but allowed free model-authored executive and per-event text. Audit action/timestamp membership carried no binding between an event and the permissible factual claim/actor. A syntactically valid AI-cause assertion therefore passed even when that event contained only advisory classification. The actual historical output and the retained `baseline-causes.json` demonstrate this gap. Copying the three STAFF fields correctly elsewhere in the result did not fix the false timeline attribution.

**Fix and regression design.** New owner `apps/api/src/ai/resolution-summary-facts.ts` supplies an executive text explicitly attributed to the STAFF record and exact action-level labels. Whole quoted fields fit within 800 characters or are omitted from the executive; all three persisted public resolution fields remain verbatim. COMPLETE_AI_ANALYSIS explicitly states classification/priority and that the cause was not verified. MESSAGE uses the supplied USER/STAFF/MANAGER provenance. No APN-specific blacklist or keyword-based actor inference is used.

`executeSummary` selects the latest 50 SUCCEEDED allowlisted public audits at/before resolvedAt, carries actorType, and reverses createdAt/id order into chronology. The fact owner rejects incompatible known action/actor pairs, invalid/decreasing timestamps and duplicate IDs. Missing public events fail closed. The native format and `validateSummaryFacts` require the exact executive and event/text pairing; selected event indices must strictly increase. Backend timestamps and duration arithmetic remain authoritative. Private notes and AI-review/collaboration metadata are excluded before prompt assembly. Normal RESOLVE and explicit retry share prompt identity `resolution-summary.m8.v5`; public schema remains `resolution-summary.m8.v3`.

## AI-EMB-01 — any background exception permanently pauses all backfill

**Observed symptom.** The historical demo log recorded `request.embedding.deferred / REQUEST_EMBEDDING_UNAVAILABLE` at 09:23:31 local time. Seven of eight eligible requests had current-version vectors until an operator restarted that demo API; index coverage then became 8/8. The generic worker log did not retain the original exception type, stage, request/version or retry state. Rapid business-version changes made STALE_CONTEXT plausible, but do not prove that it caused this particular failure.

**Expected contract and owners.** `apps/api/src/ai/tools/request-vectors.ts::index/next`, `ai/analysis-worker.ts`, the embedding adapter and `knowledge/rag-health.ts` own indexing, lifecycle and dependency readiness. [RAG_SPEC](../specs/RAG_SPEC.md) requires compatible current-version vectors, no stale publication/duplicate logical row, bounded failure handling and safe observability. AI/backfill cannot alter Request versions, business history, assignment, SLA or notifications.

**Confirmed causal mechanism.** Release `RequestVectors.next` tests a process-local `backgroundPaused` flag, and its catch sets that flag after every exception without classifying it. All later background calls return before probe/scan/index; only constructing a new instance clears the flag. The scan also sorts newest updatedAt first, allowing one repeatedly changing candidate to hide pending requests. A retained controlled test injected retryable EMBEDDING_UNAVAILABLE: three next calls produced one provider invocation and a permanent pause. That test proves the all-errors pause defect independently of the unrecorded original exception. It does not prove the historical fault was transient, stale, a database outage or a runtime update.

**Fix and regression design.** Candidate `RequestVectors` records safe correlation/stage/request/version/category/errorType and classifies failures. Stale context leaves READY with no global backoff and advances a circular ID cursor. Retryable provider/database/timeout errors enter RETRY_WAIT at 1/2/4 seconds, capped at 60 seconds after completion. Worker shutdown/cancel yields STOPPED for the canceled call; a fresh lifecycle can resume. Non-retryable model/vector/dimension/config errors and unexpected exceptions remain BLOCKED and observable. An unexpected message is never logged; only a safe type/category is retained. Successful work clears failure state and emits recovery metadata. An outage can continue periodic bounded retries; this is not a finite total retry count or success during an outage.

The worker admits at most one 30-second background call at a time when higher-priority AI work is absent. Inference occurs outside the transaction. Publication rechecks version, CANCELED eligibility and cancellation under the existing share lock; the existing unique key deduplicates concurrent inserts. The cached/probed identity and returned batch must agree. RAG readiness separately reports `REQUEST_INDEX_INCOMPLETE` when eligible current vectors are missing and reports a BLOCKED indexing error; provider UP alone is insufficient. No migration, queue table, new dependency, model change or manual vector insertion is involved.

`apps/api/test/knowledge.test.mjs` verifies bounded transient/backoff behavior, stale recovery, prolonged database outage/backoff cap, permanent mismatches, safe unexpected exceptions, overlapping calls/cancel and readiness. `apps/api/test/ai-stability.integration.test.mjs` uses real isolated PostgreSQL and twelve new synthetic requests with a controllable embedding fixture: stale writes, repeated hot-request races/fairness, two transient failures then automatic recovery, digest/dimension mismatch, concurrent deduplication, CANCELED during inference, graceful AnalysisWorker shutdown and fresh-worker recovery, and missing/current index readiness. It compares business rows before/after backfill. `recovery-m2.json` records exit 0; `recovery-m2.log` records nine tests passed, zero fail/skip, 2,037.793 ms total test duration.

The expanded final `recovery-m2-1.json/log` separately records ten tests PASS, including explicit EMB-04 provider DOWN→UP, truthful RAG readiness and working scoped/manual/stale-protected operations. `runtime-lifecycle.json` and `runtime-handoff.json` separately measure an idle owned API stop/start, real compatible16/16index and production retrieval with the five closed workflows' protected state unchanged. These later measurements supplement the retained nine-test result; they do not identify the original swallowed exception or claim that fixture recovery is a live host outage.

**Measurement limits.** Those integration tests use a fixture provider and controlled clock to exercise backoff without waiting real minutes. The graceful shutdown test invokes the actual worker lifecycle method with real request-vector PostgreSQL operations; it is not an OS-process/API-container restart test. Its readiness test controls corpus/provider health while the request-index query is real. These are deterministic causal/regression checks, not live Ollama inference, hardware latency or proof of the complete live N/N/retrieval gate. New live inference/backfill/retrieval and actual runtime observations must be reported separately in verification. The historical exception is still **NOT_RECORDED**; the repaired failure classes are established by source and controlled reproduction rather than guessed chronology.
