# Request filters and private saved views

M23 authority: direct user EXECUTE on4 October2026, limited to M23. This document owns filter semantics; AUTHORIZATION_SPEC owns scope, API_SPEC transport and DATABASE_SPEC storage. [Pre-edit plan](../v1.3/M23_SAVED_VIEWS_FILTERS_IMPLEMENTATION_PLAN.md).

`packages/contracts/src/request-filters.ts` is the canonical strict schema/URL adapter. RequestQueryService is the only query executor: current backend Request scope AND filters AND route-specific queue/approval scope AND keyset cursor. USER owns createdById; STAFF currentAssigneeId; MANAGER existing A01 organization. A view never supplies authorization predicates or results. Every ordinary list call validates independently of saved-view reads.

Scalar status/priority/category use existing enums. Optional from/to are UTC creation instants, inclusive from/exclusive to, normalized to ISO and compared as instants, from<to. All three roles may use these five fields. Optional assigneeId is MANAGER-only, a current active STAFF UUID within existing A01; inactive/missing/wrong-role references yield generic422, no metadata. Nonmanager assigneeId now returns403: this deliberately narrows the formerly permissive hidden transport field to the existing manager directory capability. Role changes cannot preserve a broader filter capability. Staff queue still restricts ASSIGNED/IN_PROGRESS/WAITING_USER/RESOLVED; approvals still require PENDING_APPROVAL plus existing reviewKind. Fixed sort is createdAt DESC,id DESC; no new sort API.

Request-list search is not implemented server-side. The existing “Tìm trong trang” searches only current-page code/title; it is transient and never saved. No team, SLA, alert-count, routing, template, note/watch/mention or analytics filter is added. Pagination limit/cursor, page, old sort/search URL values, results/counts and permissions are never persisted.

Private SavedRequestView v1 stores only the six canonical filter fields. All fields are optional. Empty filters mean no added restriction. Applying a view first GETs owned/current-role-validated detail, replaces all managed fields, removes cursor/page/sort/search and resets local page search, then uses the ordinary list endpoint. Omitted fields clear previous restrictions; sorting returns to the fixed default. Preserve unrelated shell/navigation URL params. A selected `view` URL value is only UI identity and never reaches the Request API as authority. Back/forward restores actual canonical filters and pagination; a malformed URL blocks the query with a recoverable reset instead of broadening it. The separate in-memory current-page search is not part of the saved definition.

Only explicit create/update persists preferences. Dirty status compares the actual applied canonical filter values, never draft form values; no autosave, login default, pin/reorder or sharing. Each apply refetches the definition. Invalid/schema-unsupported/current-role-incompatible/reference-unavailable views expose only ID, bounded safe name, version and reason code to their owner. No filter metadata or partial execution. Such rows remain removable with expectedVersion, or replaceable using a fully valid definition. Valid peers and manual filters work when one view is unavailable or the Saved Views API fails.
