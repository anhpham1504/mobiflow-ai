## Frozen implementation contract

- Keep recommendationSchema/Recommendation and recommendationVersion as V1 exports. Add recommendationV2Version, recommendationV2Schema, RecommendationV2, recommendationAnySchema/AnyRecommendation, isRecommendationV2 and recommendationActions helpers. New model payload carries schemaVersion= recommendation.v2; V1 historical payload remains intact.
- V2 retains validated suggestedPriority/team/staff/SLA, procedureSources, similarCaseAlert and evidenceStatus for existing domain provenance, but replaces legacy actions/confidence with suggestedChecklist and the new explanatory fields. summary <=1200, reasonSummary <=1000, main action text <=500; checklist <=10 items, each <=500 with real SOP source IDs. No business/tool command fields.
- classification is the supplied validated category/subcategory and suggested priority; enforce compatible taxonomy and snapshot agreement. Main action is one existing workflow vocabulary value START_WORK, REQUEST_USER_INFO or RESOLVE, an advisory future step with prerequisites, never a new executable endpoint. Missing information must cover exactly the analysis missing-field set, <=6, with question/impact <=300 each; values are not invented.
- Evidence <=11 typed REQUEST/KNOWLEDGE/HISTORICAL_REQUEST references, excerpt <=500 and explanation relevance <=300. References must belong to the supplied snapshot; excerpts must be exact bounded substrings of real context, not invented quotes. Relevance is a concise model explanation, not a probability. Source metadata is backend-owned. A current request context snapshot (ID/version/state/title/description/approved metadata/canonical SLA or null) extends the V2 evidence schema; V1 evidence remains readable.
- Zero SOP results mean insufficient procedural evidence and no procedureSources/checklist. Request-grounded summary and questions remain possible. Warnings <=10, explicit bounded codes/text/reference membership; missing/insufficient flags must agree with snapshot/output. SLA risk is allowed only if an actual canonical SLA snapshot supports it; stale is computed live on read/review. No model-derived SLA math or score.
- Model/parser bound output to 32 KiB, strict unknown-field rejection and finite retries. Preserve both prompt versions, native schema constraints and safe failure/attempt telemetry. Parse again at publication and review; enforce run version and snapshot identity. Unsupported/invalid stored output returns safe failure rather than raw JSON.
- V2 currentness requires matching Request version and generated state plus latest noninvalidated pending artifact; reviewed artifacts remain readable with original and separately recorded finalDecision/managerChanges/reviewer/time. Duplicate/replayed review returns 409 with no writes. Recheck source/candidate/policy and active identity inside locked transactions. Generation superseding a pending V2 invalidates it without rewriting suggestions or Request.
- Existing shared review payload carries expectedVersion/reviewKind/recommendationId, modification finalDecision and reject reason. V2 modification records that human plan, without applying it to Request. No new generic mutation API. Add OpenAPI operation IDs/input/output/error schemas and no-store.

## UI and security

V2 queue metadata binds the exact initiating refresh-session SID privately. Recheck it before request embedding, each fixed tool/model attempt and under publication locks. Exclude metadata from strict public evidence, prompts and API projections. A consumed/revoked/expired SID fails closed, including browser refresh rotation during unfinished work; a new explicit generation uses the new session. Historical V1 snapshots without metadata remain compatible. Isolated API test runners use owned loopback port 33014 (browser 3001) and fail if occupied.

Measured prompt revisions are retained. Final native generation format `grounded-recommendation.v2.4` uses draft-7 tuple `items` for required current-request evidence, exact missing questions and missing/insufficient warnings. Native bounds fit inside the unchanged public schema: three evidence items, two procedure sources, four checklist steps; summary/reason 240, step text 180, checklist/warning 120, relevance/question/impact 90 characters. Request excerpt binds real title; knowledge/historical excerpts bind bounded real text. This constrains generation, without filling, repairing or trusting model output after generation; the strict backend parser independently validates it. No token/model/retry-budget increase or fabricated confidence.

Use current manager request-detail panel/shell. Clearly separate AI suggestion from manager agreement/modification/rejection and subsequent explicit business approval. STAFF benefits through approved human-authored/approved plans under existing projections, not new access to manager evidence. Show next-step advisory label, grounded sources/excerpts, missing questions/impact, checklist, warnings, time/version and review status; original V1 still readable. V2 has no confidence/ranking score presentation. Preserve async loading/empty/invalid/error/retry/stale/permission-lost behavior; abort/ignore superseded generation/poll results, clear old request data. Escape all AI text; no raw HTML. Visible focus and keyboard controls, 360/768/1440/1920 overflow/Axe checks.
